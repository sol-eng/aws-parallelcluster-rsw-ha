Pulumi

1 Auxiliary services via Pulumi

Posit Workbench in a load-balanced setup needs a PostgreSQL database, and a distributed HPC cluster needs a directory service for users. This setup uses AWS SimpleAD. A small EC2 instance, the jump host, is joined to SimpleAD and uses adcli and expect scripts to create users programmatically.

The Pulumi program in the pulumi/ folder creates:

  • SimpleAD, plus the jump host joined to it
  • PostgreSQL databases for Workbench (pwb) and its audit log (audit), and a MySQL database for Slurm accounting
  • Secrets Manager secrets for the AD, Slurm DB and user passwords, and a secure cookie key for Workbench
  • An EC2 key pair, IAM policies and security groups used by the cluster
  • An S3 bucket for the image build and cluster scripts
  • An external and an internal Application Load Balancer with HTTPS listeners, plus Route53 records for both

2 Prerequisites

  • Pulumi, logged in to a backend (pulumi login)
  • uv, which Pulumi uses to manage the Python environment
  • just
  • AWS credentials for the target account and region
  • An existing VPC whose Name tag matches vpc_name_tag (default shared), with subnets whose Name tags contain public and private. The private subnets must span at least two availability zones (SimpleAD requirement) and need outbound internet access (NAT).
  • An existing Route53 hosted zone (dns_zone) and an ACM certificate in status ISSUED that covers *.<dns_subdomain>.<dns_zone> (or whatever you set as acm_domain)
  • Network access to the private subnets on port 22 from the machine running pulumi up (VPN, Direct Connect, or running Pulumi from an instance in the VPC). Pulumi configures the jump host over SSH on its private IP.

3 How to set up

In the pulumi/ folder, create a stack. The stack name must be the same as the ParallelCluster cluster name you use later, because the target groups and DNS records are named after the stack.

cd pulumi
pulumi stack init <CLUSTERNAME>
pulumi config set aws:region eu-west-1
pulumi config set region eu-west-1
pulumi config set email you@example.com
pulumi config set billing_code my-project
pulumi config set dns_zone example.com
pulumi config set dns_subdomain hpc          # optional

Add your Workbench license, either as a key or as a license file. It is stored in AWS Secrets Manager, and only the login nodes can read it:

pulumi config set --secret pwb_license_key XXXX-XXXX-XXXX-XXXX-XXXX-XXXX-XXXX
# or
pulumi config set pwb_license_file /path/to/workbench.lic

Then deploy everything and create 10 users:

just up

just up runs pulumi up -y followed by just create-users. To create a different number of users later, run just create-users <N>.

3.1 Configuration

NoteUpgrading an existing stack

Stacks created before these settings existed need dns_zone (and dns_subdomain if the old names were <stack>.pcluster.<zone>). To keep the existing jump host, also set jumphost_ubuntu focal and jumphost_instance_profile to the profile it had. Changing either replaces or modifies the jump host. Always run pulumi preview first.

3.2 Users and passwords

Users are named positXXXX, where XXXX is a zero-padded number (posit0001, posit0002, …). They all share one password, which is generated by Pulumi and stored in Secrets Manager. You can read it with

pulumi stack output posit_user_pass --show-secrets

posit0001 additionally gets passwordless sudo on all cluster nodes.

All generated passwords are random strings of 16 characters (20 for the user password) with at least one lower-case letter, one upper-case letter and one digit. The passwords needed by ParallelCluster (AD, Slurm DB) are also stored in AWS Secrets Manager.

User creation is done by server-side-files/config/useradd.sh on the jump host. It creates up to 40 users in parallel and verifies each one with pamtester, retrying if needed.

3.3 Outputs used downstream

image/build-image.sh and parallelcluster/deploy.sh read the stack outputs directly, so you don’t need to copy values around. The most important ones:

Output Used for
s3_bucket_id image scripts, cluster scripts
vpc_private_subnet, ssh_security_group image build instance, cluster nodes
rsw_security_group_https / _nohttps login nodes
rsw_db_*, rsw_audit_db_* Workbench database.conf, audit-database.conf
slurm_db_endpoint, slurm_db_name, slurm_db_user, slurm_db_pass_arn Slurm accounting
ad_dns_1, ad_domain, ad_password_arn DirectoryService section and /etc/hosts
iam_elb_access, iam_s3_access, iam_ec2_runinstances node IAM policies
secure_cookie_key Workbench secure-cookie-key
pwb_url_ext, pwb_url_int Workbench URLs, session callback address
alb_target_group_ext_arn, alb_target_group_int_arn target groups the login nodes register with
pwb_license_secret_arn, iam_license_access Workbench license secret and the policy that lets login nodes read it
jump_host_private_ip, private_key_ssh SSH access to the jump host

Run pulumi stack output to see all of them.

3.4 Accessing the jump host

pulumi stack output private_key_ssh --show-secrets > jumphost.pem && chmod 600 jumphost.pem
ssh -i jumphost.pem ubuntu@$(pulumi stack output jump_host_private_ip)

*.pem files are ignored by git, but delete the key when you are done.
